# WallGraph

[中文](README.zh-CN.md) · [Use cases](docs/use-cases.md) · [Train your model](docs/training-guide.md) · [Core methods](docs/methods.md) · [Validation](docs/validation.md) · [Releases](https://github.com/crown-sports/wallgraph/releases)

A floor-plan mask locates walls. A spatial application also needs their turns, junctions, and loops. WallGraph carries those pixels into original-coordinate polylines and an inspectable connection graph, while keeping the model and geometry stages replaceable.

Use it to connect an existing wall model to a drawing-review interface, compare model and processing choices, or supply aligned masks to PlanRegions. [Use cases](docs/use-cases.md) show what you can build and what inputs you need. The [training guide](docs/training-guide.md) walks through imports, data checks, training, export, and independent evaluation.

**Status: experimental engineering toolkit.** No pretrained weights or real datasets are distributed. Real drawings require your own appropriately licensed model. The model-free demo detects dark ink, including text and furniture; it is an interface example, not a trained wall detector.

## Problem and approach

A segmentation mask does not describe where walls connect, which paths form loops, or how coordinates survive resizing. Model loading, preprocessing, geometry, and application logic often become coupled, making these properties difficult to validate.

WallGraph restores probabilities to original image coordinates before cleanup and graph tracing. A backend can change without rewriting the geometry; a vectorizer can change without altering the segmentation mask. Configuration and output contracts make those choices visible. Paths preserve diagonal geometry and closed-loop anchors.

## Core technical choices

| Choice | What it makes usable |
| --- | --- |
| Junction clustering and skeleton edge tracing | Explicit node references, polyline paths, and closed-loop anchors |
| Separate pixel evidence and geometry | Original coordinates, retained masks, pixel thickness, and probability confidence |
| Probability fusion before thresholding | Optional overlapping tiles without hard binary seams; no claimed accuracy gain from this untested option |
| Compact private-data training | A U-Net-style baseline with GroupNorm, padding-aware loss, validation selection, and ONNX export |

The training baseline adapts [U-Net](https://arxiv.org/abs/1505.04597) and [Group Normalization](https://arxiv.org/abs/1803.08494); thinning uses the library's Zhang–Suen implementation. [Methods and papers](docs/methods.md) map each reference to actual code and explain the adaptation scope. [Reproduction notes](docs/reproduction.md) describe finding annotations, excluding padding, missing thin walls, and checking export precision. These are established methods organized into an independently implemented toolkit; no original-paper result or new foundational algorithm is claimed.

## Install and run

Requires Python 3.10 or newer. The package is currently released through GitHub, not PyPI.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install "git+https://github.com/crown-sports/wallgraph.git@v0.1.1"
wallgraph demo --output runs/demo
```

Alternatively, install the wheel from the tagged [release](https://github.com/crown-sports/wallgraph/releases/tag/v0.1.1). See [release instructions](docs/releasing.md) for checksum verification.

![The single generated demo drawing](examples/simple.png)

This is the only image committed to the repository. It is generated by `draw_demo()` and is neither training data nor an accuracy benchmark. The demo produces six wall polylines; its mask can be passed to [PlanRegions](https://github.com/crown-sports/planregions) to obtain three regions.

When changing a model or threshold, use [PlanRegions comparison](https://github.com/crown-sports/planregions/blob/main/docs/comparison.md) to locate region merges, splits, and disappearances in the downstream output. A small wall-pixel change can have a large spatial effect.

Use a real segmentation model:

```bash
python -m pip install "wallgraph[onnx] @ git+https://github.com/crown-sports/wallgraph.git@v0.1.1"
wallgraph detect --image /private/plan.png --model /private/wall.onnx \
  --preprocess rgb --wall-classes 1 --device cpu --output runs/prediction
```

The ONNX adapter expects one float32 NCHW, three-channel input normalized to 0–1, and binary or multiclass segmentation logits. Binary models use `--wall-classes 1`; multiclass models require explicit wall class IDs. Set `--output-kind probabilities` for probability outputs. Fixed input dimensions are read from the model; dynamic spatial dimensions use `--input-size H W`.

Available preprocessing modes are `rgb`, `gray`, and `clahe`; they are part of the model contract and must match training. For large images, `--tile-size 1024 --overlap 128` fuses probabilities before thresholding. Tiling is optional and may lose global context. Morphological closing is off by default; enable it explicitly with `--close-radius` and validate door openings. CUDA setup and strict device checks are described in [runtime notes](docs/runtime.md).

## Python API and output

```python
from wallgraph import WallConfig, WallPipeline
from wallgraph.backends import InkBackend
from wallgraph.io import draw_demo

result = WallPipeline(InkBackend(), WallConfig()).run(draw_demo())
mask = result.mask
graph = result.to_dict()
```

`WallBackend` and `Vectorizer` are replaceable strategies. The ONNX backend reuses its session; importing the package does not initialize a GPU or download weights.

| File | Meaning |
| --- | --- |
| `walls.png` | Binary mask: 255 is wall, 0 is background |
| `walls.json` | `wallgraph/1` nodes, polyline paths, thickness, confidence, configuration, and stage timings |
| `walls.svg` | Vector preview in original pixel coordinates |

Coordinates use the original image, origin at the upper left, x right, y down. Segment endpoints reference graph nodes; a closed loop can reference the same node at both ends. Thickness is a pixel estimate from the distance transform. Confidence is mean predicted wall probability along the skeleton, not calibrated whole-wall correctness. No physical scale or square-meter measurement is inferred.

## What the experiments show

Thirty annotated test drawings, selected after freezing the validation configuration, gave these image-averaged wall IoUs using an external private model:

| Reference or pipeline | Macro IoU |
| --- | ---: |
| Legacy final API mask | 0.78478 |
| Legacy raw segmentation reference | 0.86334 |
| WallGraph default configuration | 0.84089 |
| WallGraph validation-selected closing radius 2 | 0.84203 |

The selected configuration improves over the final API mask but falls below the raw reference. It also has lower wall recall; downstream region PQ fell from 0.68034 to 0.56580. The legacy model's training exposure is unknown. These results do not establish a production replacement or general superiority.

The new SmallUNet trained on 90 real annotated drawings reached test macro IoU 0.59297 and is not distributed as production weights. Default-runtime export checks also exceeded the chosen maximum-probability-error threshold on one validation tensor. [Validation](docs/validation.md) records the splits, confidence intervals, timing scopes, negative results, and numerical limitations.

## Private training and evaluation

From a local source checkout, install the training extra as below. Keep images, annotations, and manifests outside the public repository. JSONL records contain `image`, `mask`, and `group`; paths resolve from the manifest directory. A group represents the original floor plan, including all crops and augmentations. Masks contain 0 for background and 1 or 255 for wall.

```bash
python -m pip install -e '.[train]'
wallgraph train --train-manifest /private/train.jsonl --val-manifest /private/val.jsonl \
  --device cuda --size 512 --epochs 20 --output /private/run
wallgraph export-onnx --checkpoint /private/run/best.pt \
  --size 512 --output /private/run/model.onnx
wallgraph evaluate --manifest /private/test.jsonl --model /private/run/model.onnx \
  --output /private/reports/walls.json
wallgraph benchmark --images /private/plan.png --model /private/wall.onnx \
  --device cpu --warmup 1 --repeats 3 --output /private/reports/latency.json
```

Training uses BCE+Dice and AdamW, excludes letterbox padding, checks group and identical-file overlap between training and validation, and selects the best validation IoU. Users must also keep the test split independent. Evaluation reports pixel IoU/F1 and skeleton coverage; coverage is not a graph-connectivity metric.
