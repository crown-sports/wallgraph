# WallGraph 能帮你做什么

[English](use-cases.md) · [快速开始](../README.zh-CN.md) · [核心方法](methods.zh-CN.md) · [实测结果](results.md)

模型能指出哪些像素是墙，应用还需要知道墙在哪里转弯、如何相接。WallGraph 把这一步整理成可接入、可检查的工具：保留墙体掩膜，提取原图坐标下的路径和节点，让模型与几何处理可以分别改进。

## 从手头的问题开始

| 你要完成的事 | 输入 | 能拿到什么 | 还需要你提供什么 |
| --- | --- | --- | --- |
| 为图纸复核工具增加墙体结构 | RGB 图纸和兼容的 ONNX 墙体模型 | 墙路径、连接节点、掩膜和 SVG 预览 | 复核界面与业务验收标准 |
| 比较模型或后处理方案 | 有独立标注的图纸和待比较配置 | 像素 IoU/F1、骨架覆盖指标、分阶段耗时和几何结果 | 留出的测试集与单独的连接关系检查 |
| 将墙体结果交给区域分析 | 一份墙体结果 | PlanRegions 可读取的二值掩膜和元数据 | 开放边界、分隔线等额外依据 |
| 接入其他推理框架 | 返回原图对齐概率图的 Python 后端 | 复用同一套清理和图结构提取流程 | 推理适配器及准确的预处理约定 |

做复核界面时，可以按 `walls.json` 绘制墙路径，再沿端点编号找到连接节点；`walls.png` 则保留对应的像素依据。哪里断开、哪里多出闭环，都有具体结果可查。图纸是否正确，仍需结合业务判断。

## 两个项目连起来试一次

按两个项目的 README 安装后，运行：

```bash
wallgraph demo --output runs/walls
planregions detect --walls runs/walls/walls.png \
  --wall-metadata runs/walls/walls.json --output runs/regions
```

这一张程序生成的简单图会得到 6 条墙路径、3 个区域。WallGraph 输出 `walls.png`、`walls.json` 和 `walls.svg`；[PlanRegions](https://github.com/crown-sports/planregions) 接着输出精确的实例标签图和区域多边形。传入元数据时，会先核对尺寸、坐标和墙体像素取值。这能验证接口衔接，不能代表真实图纸的识别精度。

接入真实模型时，请对照 [README 的输入约定](../README.zh-CN.md)。输入尺寸能对上还不够，颜色顺序、归一化、类别编号和输出含义都必须与训练时一致。

## 适用边界也要说清楚

内置墨迹检测会把文字和家具一起选中；真实墙体识别需要自备有使用权的模型。项目目前没有交互编辑器、DXF/BIM 导出、比例尺推断或门通行图。坐标和厚度以像素计，墙体连接也不能直接当作行走路线。

SVG 看起来整齐，不代表连接关系准确。已有测试发现，新完整流程的墙体召回率和下游区域结果下降，即使它优于其中一个后处理掩膜基线。请用[实测报告](results.md)确定自己的验收方法。如果只需要二值掩膜，未必需要增加图结构提取这一步。

## 30 秒介绍

> WallGraph 帮助开发者把平面图中的墙体预测变成可检查的结构：掩膜、墙路径、连接节点和闭环，统一保留原图坐标。你提供模型，它提供可替换的推理与几何处理接口、命令行和评测工具，也能把结果直接交给 PlanRegions 分析区域。项目目前处于实验阶段，代码和实测局限一并公开，方便你搭建流程、定位问题，再按自己的场景改进。
