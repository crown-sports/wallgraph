# 从跑通模型到看懂结果

[English](reproduction.md) · [方法与论文](methods.zh-CN.md) · [完整验证](validation.md)

这次工程复现最有价值的经验，是逐步把“程序能跑”与“结果可用”之间的差距找出来。以下记录来自实际执行的训练、推理和配对评测。它描述改编方法在图纸任务上的实跑，没有重做 U-Net 原论文的医学实验。

## 先找标注，再定比较方式

最初的四张真实图纸只能检查链路与耗时。沿原工程的数据加载约定继续查找，才确认了 `F1_scaled.png`、`model.svg` 和官方 split 的标注来源。随后以固定 seed 选取 90/15/30 张训练、验证、测试图；配置只在验证集选择，测试负责回答最终问题。[数据论文](https://arxiv.org/abs/1904.01920) 提供出处，私人名单和权重不进入仓库。

墙体真值含标注中的门窗开口结构。把它视为完全封闭的屏障，会混淆像素分割与房间分隔。配对实验因此同时保留旧原始分割、旧最终 API 掩码和新输出，避免只挑一个较弱参照来展示改善。

## 分辨率、padding 与训练预算

非方形图先 letterbox 到 512；padding 用 valid mask 从损失和验证计数中排除。SmallUNet 采用 16/32/64 通道、两级下采样、GroupNorm/SiLU、BCE+Dice 和 AdamW。90 张真实标注在 RTX 5090 上训练 20 个 epoch，batch 4、seed 42，验证选中第 18 个 epoch。

训练尺寸下的验证 micro IoU 为 0.61542；原图坐标的测试 macro IoU 为 0.59297。两者的数据和聚合方式不同。旧参考模型输入 1024，训练预算和数据暴露未知，因此这次结果回答的是新基线能达到什么程度，不能证明 U-Net 架构优劣，也不能替代现有模型。

## 像素指标提升后的下游失误

新选定输出的墙体 macro IoU 为 0.84203，超过旧最终 API 的 0.78478，但低于旧原始分割的 0.86334。平均召回率从 0.95247 降至 0.88687；新两阶段区域 PQ 从 0.68034 降到 0.56580。私有失败样本中可见细内墙缺口把多个房间连成一个区域。

这个结果改变了下一步的评价重点：除了像素 IoU，还需要检查薄墙召回、闭合性和区域实例。已有 skeleton F1 只测覆盖，真实连接图标注仍缺失；全部错误的人工原因分类也尚未完成。

## 导出成功之后还要比较数值

在一张固定验证张量上，ORT 默认 CPU/CUDA 相对 PyTorch CPU 的最大概率误差为 0.002421/0.001225，均超过预设 0.001。CUDA 禁用 TF32 后降至 0.000003636；CPU 差异仍未定位。测试成绩使用实际默认 CUDA 配置，没有据这张诊断重新选模。[运行时说明](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#use_tf32) 解释 TF32 选项，一张张量也不足以建立普遍误差界。

## 复用这套实验时

仓库提供训练、评估与计时命令；参数记录、组隔离、原图坐标和设备核验可以直接复用。准备自己的授权数据时，先固定真值定义和 train/val/test 分组，用验证集选配置，再保留独立测试。默认关闭补墙和切片，需要单独验证后开启。

公开包没有本轮冻结名单与参考权重，因此无法仅凭下载包重建这张配对成绩表。发布的是方法、代码和实验协议。继续改进后应使用新的保留集，避免反复用这 30 张测试选方案。图纸、标注与新研究权重保持私有。
