# 实测记录（更新于 2026-10-04）

当前结论：新流水线在本轮 30 张带标注图上优于旧系统的最终墙体掩码，但低于旧系统的原始分割参考。小型独立训练模型尚不能替代既有权重。以下为工程回归实验，不宣称生产精度或基础算法突破。

## 数据与冻结协议

沿已有工程的加载约定找到 [CubiCasa5k](https://github.com/CubiCasa/CubiCasa5k) 的图像与 SVG 标注。数据来自 [官方 Zenodo 发布](https://zenodo.org/records/2613548)，按需下载并核验 ZIP CRC 与 SHA-256。图片、标注、名单、权重和逐图输出保留在私有目录，不包含在发布包中。数据为 CC BY-NC 4.0，新代码的 MIT 不覆盖它。

从官方 train/val/test 中分别抽取 90/15/30 张，对 colorful、high_quality、high_quality_architectural 三个来源均衡抽样，选择 seed 为 20261003，推理前确定样本。原图组及完全相同的图像字节跨 split 不重复。每个测试来源 10 张，因此结果代表这个均衡子集。既有权重的训练暴露未知，不能确认它未见过官方测试图；新训练模型未使用这些测试图。

墙体真值为 SVG 结构 Wall 标签 2，含门窗开口结构、排除栏杆。这个定义与完全不透行的物理屏障不同。新旧使用同一个外部 1024×1024 墙体模型，摘要见下方先期记录；旧原生分类路由、预处理和后处理保留，新系统使用固定 CLAHE 和类别 `[1, 2]`。30 张测试图的旧路由均选中此模型，但整个系统仍不是只改代码组织的等价变换。

仅用 15 张验证图选择配置。四个候选的平均 IoU 分别为默认阈值 0.5/半径 0：0.84196；阈值 0.5/半径 2：0.84343；阈值 0.6/半径 0：0.80287；阈值 0.7/半径 0：0.72998。测试前冻结阈值 0.5、闭运算半径 2，库的通用默认值仍关闭补墙。

## 30 张测试图的墙体质量

全部完成，0 个解析／推理失败。原图尺寸下正值为墙；macro 每图等权，micro 汇总所有像素的 TP/FP/FN。

| 输出阶段 | macro IoU | macro F1 | micro IoU | micro F1 |
| --- | ---: | ---: | ---: | ---: |
| 旧最终 API 墙体掩码 | 0.78478 | 0.87768 | 0.76436 | 0.86645 |
| 旧原始分割参考，去 padding 后恢复原图 | 0.86334 | 0.92555 | 0.85357 | 0.92100 |
| 新默认配置 | 0.84089 | 0.91190 | 0.81948 | 0.90078 |
| 新验证选定配置，半径 2 | 0.84203 | 0.91259 | 0.82097 | 0.90168 |

逐图配对、在三个来源内 bootstrap 10,000 次，seed 20261003，百分位 95% 区间。新选定配置相对旧最终输出的平均 IoU 差为 **+5.72 个百分点，[+4.94, +6.52]**，30 张均提升；相对旧原始分割为 **−2.13 个百分点，[−3.25, −1.10]**，6 张提升、24 张下降。不能只选旧最终输出就宣称所有精度都改善。

新配置的平均 precision/recall 为 0.94116/0.88687，旧最终为 0.81499/0.95247。误墙减少、漏墙增多。骨架覆盖 F1 为旧最终 0.94347、旧原始 0.95910、新选定 0.95770；该指标将一方骨架与另一方经两次四邻域膨胀的墙体掩码比较，不测连接图正确性。区域端到端 PQ 从旧 0.68034 降到新 0.56580，像素改善没有证明空间划分改善。

## 同机配对性能与扰动

同一服务器、4 个 CPU 推理线程，使用每个来源一张预先选定的验证图与 4 张已有真实图，共 7 张。每张每方法预热 1 次、测量 3 次，共 21 次，包括预处理、推理、清理和矢量化，排除文件 I/O。新会话复用，构造时间排除；旧原生 API 每次创建分类和墙体会话，其开销包含在计时中。没有调用失败。

| 方法 | 中位耗时 | P95 |
| --- | ---: | ---: |
| 旧完整墙体流程，CPU | 3207.78 ms | 4190.56 ms |
| 新完整墙体流程，CPU | 1446.38 ms | 1849.59 ms |
| 新完整墙体流程，RTX 5090 CUDA | 166.65 ms | 599.93 ms |

结果说明本轮原生部署和会话复用下的耗时变化，不能归因于单一算法，也不足以估计生产尾延迟。新 CPU/CUDA 掩码间 IoU 最低为 0.999617，有少量阈值边缘差异；CUDA 禁止节点回退，先期 profiling 确认外部墙体模型 149 个执行节点均在 CUDA 上。

三个固定验证样本的扰动检查：原图平均 IoU 0.83351，JPEG 质量 50 为 0.83449，噪声标准差 8 为 0.83793；旋转 90°并恢复坐标后为 0.77697，平均下降 5.65、最差下降 12.06 个百分点。没有旧流程扰动对照，也没有多次噪声重复，不能声称普遍抗噪或旋转不变。

## 新模型的真实训练与数值检查

SmallUNet 使用 16/32/64 通道、GroupNorm、SiLU、BCE+Dice、AdamW，学习率 0.001，batch 4，RGB 512×512，seed 42。在 RTX 5090 上用 90 张官方训练图、15 张验证图训练 20 个 epoch，排除 padding，按验证 micro IoU 保存最佳权重：epoch 18，训练分辨率的验证 IoU 0.61542。30 张保留测试图在原图坐标的 **macro IoU 为 0.59297、micro IoU 为 0.56866、micro F1 为 0.72502**。

该模型的训练图数、输入尺寸和预算与旧模型不同，旧训练详情未知，不能将差值归因于架构优劣。它是私有研究基线，不能作为生产替代。ONNX SHA-256 为 `152841349eae9fe40dc2a8aee3edaa72b6e5f144d05a623e048561b808498d19`，发布包不含权重。

在一张固定验证图的 512×512 张量上，比较 PyTorch CPU 与 ONNX sigmoid 概率：默认 ORT CPU 最大误差 0.002421、默认 CUDA 0.001225，均未通过预设 0.001 最大误差门槛；二值像素一致率分别为 99.99847%/99.99886%。CUDA 禁用 TF32 后最大误差为 0.000003636，二值像素全部相同。这个单张数值检查不能保证所有样本；TF32 的默认行为见 [ORT 官方说明](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#use_tf32)。

本轮共同环境为 Python 3.12.14、NumPy 1.26.4、OpenCV 4.11.0.86、SciPy 1.14.1、scikit-image 0.24.0、ORT GPU 1.26.0、PyTorch 2.8.0+cu128、CUDA 12.8、驱动 580.95.05。旧实现的依赖兼容问题通过共同固定版本解决，不把兼容异常计为识别错误。两个工程本地共 33 项测试通过，服务器 32 项通过、1 项 CPU-only 检查跳过；另有 100 个生成布局的不变量验证。图连通性人工真值、业务图纸和完整规模评测仍待补充。

## 先期记录（2026-10-03，以下描述当时状态）

使用项目已有的 4 张真实测试图和一个外部墙体 ONNX 模型，在用户授权的私有环境中实测。没有人工墙体标注，因此以下数字是性能记录，不是准确率。图像、权重和逐张输出不随公开工程发布。

输入原始尺寸（H×W）为 404×450、479×600、500×444、933×1400；模型输入 1×3×1024×1024。预处理为 RGB 灰度+两组 CLAHE，墙体类别显式配置为 `[1, 2]`，阈值 0.5，关闭补墙和切片。它验证新的通用适配器，不等同于完整复刻旧系统的分类路由和业务后处理。

每张预热 1 次、测量 3 次，共 12 次测量。所有计时排除文件 I/O、模型创建与预热，流水线计时包含清理和矢量化。

| 环境与范围 | 中位耗时 | P95 |
| --- | ---: | ---: |
| RTX 5090，墙体完整流水线 | 104.87 ms | 165.65 ms |
| RTX 5090，仅模型推理与预处理 | 54.57 ms | 59.66 ms |

GPU 环境：Python 3.12.14、PyTorch 2.8.0+cu128、CUDA 12.8、ONNX Runtime GPU 1.26.0、驱动 580.95.05、NumPy 2.5.3、OpenCV 5.0.0.93。会话列出 CUDA 和 CPU provider，但已禁用 CPU fallback；独立 profiling 检查到 149 个实际执行节点使用 CUDA，0 个节点使用 CPU。

外部墙体模型 SHA-256：`002cff7ee14aec41f3171747bbcd5ff7f0769dd56bd16084807cb97c2c615d4f`。模型仍为私有资产，不包含在源码包中。
