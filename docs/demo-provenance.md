# Six-stage figure: source and reproduction

The README’s `examples/simple.png` is the repository’s only image file. It shows one actual model execution on an original **1200×900** apartment-style drawing generated by [`tools/draw_complex_demo.py`](../tools/draw_complex_demo.py). Furniture, room labels, doors, windows and drafting marks make the input more involved than the CLI’s simple demo. The illustration contains no user attachment, real drawing, dataset image or annotation.

## What the six panels show

| Panel | Actual data displayed |
| --- | --- |
| 1. Original | The full generated RGB drawing, without cropping |
| 2. Gray input | Captured model tensor channel 0, including letterbox padding |
| 3. CLAHE20 input | Captured model tensor channel 1: CLAHE clip limit 2, grid 20×20, including padding |
| 4. Final predicted mask | The normal pipeline’s threshold, closing and small-component filtering result |
| 5. Red overlay | The same final mask over the original drawing, red opacity 0.65 |
| 6. Blue paths and nodes | All actual output polylines and connection nodes in original coordinates |

The model has **three input channels**: gray, CLAHE20 and CLAHE40 (clip limit 2, grid 40×40). The third channel is not displayed. These are captured from the tensor supplied to ONNX, not grayscale previews made afterward. Preprocessing uses bicubic aspect-preserving resizing, padding value 128, float32 division by 255 and NCHW layout. Thumbnails only resize the display; they do not feed back into inference and may omit tiny features.

The final mask and geometry were not manually corrected. This drawing supplies no wall ground truth, so it establishes neither IoU nor graph accuracy. This is not complete CAD reconstruction or door/window recognition. Inspect the mask and the geometry together. Published [validation results](validation.md), including regressions, remain unchanged.

## Run it with your own model

From a current main checkout:

```bash
python -m pip install -e '.[onnx]'
python tools/render_demo.py --model /private/wall.onnx --preprocess clahe \
  --wall-classes 1 2 --output /private/steps.png
```

With no `--image` argument, the tool generates the original complex drawing. To inspect your own image, add `--image /private/plan.png`; image data stays local. Match preprocessing, class IDs and output semantics to your own model. A different model can produce different walls, paths and nodes; the displayed result cannot be reproduced from the public repository alone because these weights are private. Generated lettering may also vary with installed fonts.

`python tools/render_demo.py --check` checks the fixed reviewed image’s hash and format. It does **not** perform private-model inference or establish model accuracy. Only this composite PNG is published; raw input exports, intermediate images, model weights and user attachments are excluded. The separate `wallgraph demo` still uses a small generated drawing and an ink thresholding baseline. Existing v0.1.2 release assets are unchanged.
